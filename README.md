# NeatWin · 人因任务排布 v3

Windows 浮动窗口整理工具，内置习惯记录器。把粗摆当作意图草稿，而不是标准答案：替你承担继续整理的成本，不把“懒得继续调整”固化成布局规则。

## 使用

发布包中的 `NeatWin.exe` 是主程序，并已内置习惯记录器；`NeatWin.Recorder.exe` 只为兼容旧工作流和需要单独运行记录器的场景保留。两者都是 Windows x64 的 framework-dependent 单文件程序，**不再附带 .NET 运行时**。运行前需安装 **Microsoft .NET 10 Desktop Runtime x64**。NeatWin 通过应用清单请求管理员权限，启动时会出现 UAC 提示，以便管理同为管理员权限的普通桌面窗口；SYSTEM、受保护进程等更高权限表面仍不会强行操作。

主窗口标题含“人因任务排布 v3”；内置记录器继续使用兼容 v2 的记录格式。使用 Smart 并主动点击整理即可，无需开启随手辅助，也无需刻意训练。

托盘新增“人因排布偏好”：允许或关闭有收益的缩放、小幅外侧出屏；调整参考信息尺度；可选输入当前工作区物理宽度与观看距离。不需要每次选择工作模式。未提供物理参数时不会猜测人眼视场角。

## 顶部直接显示四档自动整理

主界面上方直接平铺四个可点击选项：**自动关、轻度辅助、完整辅助、自动完整辅助**。没有下拉菜单，也没有第五档。“平铺”指四个控件的展示方式，不是强制窗口平铺。

| 档位 | 自动触发 | 排布方式 |
| --- | --- | --- |
| 自动关 | 不触发 | 仅手动整理 |
| 轻度辅助 | 拖动/缩放结束 | 原单窗口随手辅助 |
| 完整辅助 | 拖动/缩放结束 | 和手点相同的完整 Smart，允许调整整个工作组 |
| 自动完整辅助 | 外部窗口开关、最小化/恢复、前后台、层级、位置/大小或工作区变化 | 完整 Smart |

旧配置中误设的第五档会迁移为“自动完整辅助”，不继续后台平铺；正常工作流不再提供完整平铺按钮。

Smart 的几何整理现在更积极，但层级更保守：降低对有收益几何调整的阻力、拓宽尺寸候选，同时禁止把当前前台窗口压到组内后面，也禁止把明显被遮挡的背景窗口主动提到前面。也就是说“位置尺寸敢动，前后层级慎动”。

窗口变化约稳定 450 毫秒后合并处理，自动调用间隔至少 1 秒；拖动进行中不介入。NeatWin 自身位置/层级变化、设置窗口和撤销不会循环触发整理。很快开始的新手动纠正不被自身事件过滤吞掉。自动完整辅助在切换进入时整理一次；启动恢复模式时只建立基线，不突然重排桌面。

记录仍在原目录。`plans-*.jsonl` 分开标记 `explicit`、`follow-hand`、`automatic-gesture`、`automatic-workspace` 和 `undo`。没有再次调整仍不代表满意。

## 怎样做出决定

Smart 对同屏局部工作组比较共同观看、暂存叠放及同列关系。输入焦点不等于观看需求；后台播放器也可能需要持续可见。相同几何可能有不同用途，自动判断会保留不确定性，不声称识别了所有应用语义。

比较方案包含局部微调、并排、叠边、叠放、普通窗口层级、新的缩放／贴边／外侧空间交换／同列成组重排。尺寸可以改善，但没有无限铺满屏幕的奖励。保持 A 左、B/C 右侧同列等关系，而不是机械地把每个窗口分配到独立网格。

少量水平出屏默认开启，预算为 24 DIP 且不超过窗口宽度 3.5%，可关闭或调整。只考虑已知物理屏幕的外侧边缘，不越入相邻显示器、不侵占侧边任务栏、不上下出屏。屏外像素计入信息损失，不能刷高可见面积。边缘可能包含重要内容；几何中心只是代理，不能保证识别字幕、菜单或游戏 HUD。

相对层级不设置永久置顶、不主动抢焦点、不持续抢回层级。当前前台窗口不会被 Smart 主动压到组内后方；明显被遮挡的背景窗口也不会只因为几何候选更优就被提到前面。只调整安全的普通窗口工作组；无关窗口、对话框、永久置顶及身份／几何变化仍会限制执行。明确撤销包含几何与层级，已变化的相关组不会半套恢复。

程序区分候选、请求、实际落点及后续介入。明确撤销留下会话内局部负面反馈；普通手动后续可能表示换任务，不直接算否定；没有再修改不等于满意。只有实际核验匹配的近期结果才用于防重复漂移。

Classic 与小范围随手辅助保留。Smart 旧的强制几何填充不再覆盖任务目标；可选视频黑边功能仍作为内容提示和受任务目标约束的后处理。新版不是已验证的读心或眼动系统。

## 研究与用户画像

完整说明见 [人因任务模型 v3](docs/HUMAN_FACTORS_V3.md)：计算理性、混合主动交互、窗口管理实践、视觉注意、接近兼容性、空间任务管理、平铺／重叠对照和多窗口组操作的原始来源；逐项区分论文结论、本人明确偏好、工程初值与尚未验证的假设。

没有从历史“不缩放”频率拟合缩放厌恶，也没有把手动横移／纵移比例变成自动改动容忍度。旧数据不提供内容、真实眼动或满意标签，因此不报告虚构的意图准确率。

## 记录器与隐私

记录器现在直接集成在主程序的新“记录器”页签中：NeatWin 运行时自动记录，可在页签里暂停／继续、打开数据目录、导出 ZIP 或清空记录。独立的 `NeatWin.Recorder.exe` 仍保留兼容用途；同一时间只允许一套记录引擎写入，避免主程序和独立记录器重复采集。升级时先退出旧主程序和独立记录器，再启动新主程序；正常使用无需另外启动 Recorder。

本地目录：`%LOCALAPPDATA%\NeatWin\Recorder`。

| 文件 | 内容 |
| --- | --- |
| `adjustments-*.jsonl` | 手势前后和短期确认的几何、层级及邻居上下文 |
| `workspace-*.jsonl` | 合并后的前台、层级、几何状态变化 |
| `plans-*.jsonl` | 候选、任务解释、成本分项、拒绝理由、请求与实际结果 |
| `intent-reference.json` | 去重、衰减和限幅的弱参考 |

不保存标题、应用名、进程号、原始句柄、按键、截图或鼠标轨迹；没有自动上传。匿名编号只用于会话内对应，几何和时间仍是个人数据，不要直接提交到公开仓库。原始日志合计限制为 32 文件／32 MB／30 天，可能因容量更早淘汰。

内置记录器的暂停会停止观察日志和新的 `plans-*.jsonl` 写入；整理和实际落点核验仍工作。清空后，旧的待确认结果也不会重新写回。观察与整理诊断共用会话和匿名窗口编号。“使用记录器的弱参考”只控制读取，不控制记录。明确偏好单独保存在 `%LOCALAPPDATA%\NeatWin\human-factors.json`，不包含窗口身份或原始日志。

## 构建与验证

Windows 10 2004 或更新版本／Windows 11。运行正式版需要 **Microsoft .NET 10 Desktop Runtime x64**；源码构建需要 .NET 10 SDK。`global.json` 固定 .NET 10 系列。

```powershell
dotnet test tests/NeatWin.Tests/NeatWin.Tests.csproj -c Release
dotnet build src/NeatWin.Recorder/NeatWin.Recorder.csproj -c Release

dotnet publish src/NeatWin/NeatWin.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o artifacts/win-x64
dotnet publish src/NeatWin.Recorder/NeatWin.Recorder.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o artifacts/win-x64
```

CI 执行测试、主程序／记录器构建与发布、启动检查，保存 TRX、源码快照和程序包。Desktop smoke 单独检查原生移动生命周期、普通层级调整和恢复。以相应提交的实际结果为准，不把测试存在当成已经通过。

`tools/NeatWin.Replay` 直接使用生产 Core 做离线几何回放。旧日志只能构造假设场景，不是现场重建或真人满意率。任务可用性、补调负担和重要信息误遮挡仍需实际桌面验收。
