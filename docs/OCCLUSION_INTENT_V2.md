# 叠边、层级与意图观察 v2

本轮改进针对主动点击整理仍过于轻微的问题；不要求开启常驻随手辅助。目标不是让所有矩形无重叠，而是在并排、叠边、叠放和小幅修正之间选择可执行方案。用户的调节只是线索，不是理想布局标签。

## 主程序的实际变化

`IntentLayoutPlan` 将几何、相对层级和候选解释分开。每个显示器内形成局部工作组，比较保留、旧局部纠正、行列、多行、叠边并排、宽松／紧凑叠放以及只改变层级的方案。候选生成失败与约束拒绝分别记录。

两个宽窗口总宽略超屏幕时，保留宽度的叠边与缩窄并排同时参与比较。已叠放的多个窗口可以形成有露出入口的叠放组。明显的近中心错位作为叠放线索，但不是意图概率；窗口宽度、工作区压力和移动成本一起参与选择。不为“有变化”而强制每次重排。

遮挡按前面窗口的**并集**计算，不重复计算三窗共同覆盖的区域。评分区别总露出面积、中心区域、顶部访问带及较高的可见竖条。当前中心左右各内缩 18%、上下各内缩 8%，叠边生成上限约 22%；这些是可测试的工程取值，**不是文献证明的低信息边界**。应用可能把重要按钮放在边缘，本版并不知道。

明确 Smart 整理可以纳入露出足够顶部访问带的窗口，避免整片叠放窗口被面积阈值提前丢弃；完全遮住的窗口仍不主动唤出。固定尺寸、最小尺寸、工作区、移动预算、其他工作组及不可管理遮挡物约束保留。后处理不得重新把已经选定的叠边拆开，也不得明显恶化其可见区域。

### 相对层级而不是永久置顶

普通相对顺序和 `HWND_TOPMOST` 是不同概念。按官方 SetWindowPos 语义[8]，本版使用不激活、不改变永久置顶状态的相对次序操作。只有同一显示器上连续的一组普通可管理窗口才能重排；不越过无关应用、对话框或永久置顶窗口。

先重新捕获，核对进程身份、几何、工作区、DPI 和置顶状态；先应用、核验所需层级，再应用依赖它的位置。层级未实现时不执行那一组依赖它的几何。Windows 不提供此处的跨进程原子事务，因此仍是带校验的尽力执行，不是绝对无竞争窗口。

保持键盘焦点不等于层级永远不变：之后点击窗口，Windows／应用仍可能把它提到前面。本版不会持续抢回层级，也不会将参考窗口永久压住其他应用。

撤销也检查组内顺序与后续几何。已经被手动调整或重排的层级相关整组不执行半套还原。只成功调用位置 API 不等于应用接受尺寸，因此另有延迟结果检查。

[8] https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos

## 记录器：从落点记录升级为关系观察

新版手势 `Version: 2` 保留旧字段，并增加 `StartContext`、`EndContext`、`SettledContext`。每帧有匿名会话内窗口编号、矩形、工作区、DPI、前后顺序、前台／永久置顶／可管理标记和几何露出比例。最多 64 个窗口，超限明确标记，不能将截断背景用于新关系提取。原生句柄和进程号只在内存中做身份核验；窗口销毁后退休其编号。

`workspace-*.jsonl` 独立记录合并后的前台与状态变化。事件是“需要重新观察”的提示，尤其 `EVENT_OBJECT_REORDER` 可能是子对象变动，不能直接解释为人手重排[9]。来源不明的窗口变化不会直接训练偏好。高频事件回调只标记，250 毫秒计时器再捕获变化；不是每个事件都落盘。

真实移动／缩放事件仍等待两秒确认。新操作、跨屏、对象消失、几何变化、NeatWin 自动化标记会分类。参考提取要求邻居在操作前、结束和确认时具有匹配身份且几何未变，避免把邻居的变化算成用户想要的间距。没有继续改变仍只叫“短期稳定”，不叫满意。

新增关系样本接受横向叠边和较深叠放，而不只接受非负间距。旧 v1 数据可以继续读，但不能虚构它没有记录过的层级。摘要保持最多 128 个样本、30 天、时间去重及分散门槛；已有间距融合仍最多 25%，叠放偏好只提供不超过 0.08 的有限评分影响。默认候选已经包含叠放能力，不必等“训练成熟”才会工作。

## 整理诊断与存储

主程序在明确整理、实际随手辅助和撤销时写 `plans-*.jsonl`：候选类别、分数／拒绝原因、选中方案、请求位置和相对层级，以及约 600 毫秒后的实际观测。`requested-not-yet-verified` 不能当成功；`observed-match` 只表示观测时匹配，不能当满意；`intervened` 表示被后续操作干扰。没选出更好的方案，也不宣称桌面已经理想。

记录器导出包含 `adjustments`、`workspace`、`plans` 和弱参考。暂停记录器只暂停记录器的观察；主程序仍可在你主动整理时写诊断。要完全停止新增数据，退出两者。参考开关只影响模型读取，不是记录开关。

所有日志总量限制为 32 文件／32 MB／30 天，单文件约 2 MB 滚动；上限不保证留满 30 天。未确认的短尾数据可能因退出丢失。导出进行中其他进程仍可能写新记录，因此导出不是同一时刻的全局事务快照。

数据不自动上传，不保存标题、应用名、按键、截图或鼠标轨迹。主程序原有可选视频检测是另一项既有功能，不应将“记录器不保存截图”夸大成所有功能从不读取屏幕。

## 验证方法与不能证明的事

回归覆盖宽度不足叠边、参考窗口在前、叠放入口、遮挡并集、身份匹配、旧数据兼容、随机几何约束和重复整理。离线工具 `tools/NeatWin.Replay` 编译生产核心源码，不读 Win32，也不将私有日志传到 Actions。

旧日志缺少真实层级与可缩放属性时，回放构造两种假设层级、假定可缩放并纳入记录的邻居。回放证明候选覆盖和几何行为，**不是现场复原或意图准确率**。输出包含第二次整理是否还提出变化，避免只看第一次移动很明显。

`tools/NeatWin.DesktopSmoke` 只操作自己创建的测试窗口，检查普通层级反转、焦点／几何／永久置顶状态、恢复、过期状态拒绝，并对独立记录器的系统移动生命周期做集成检查。它不是用户手握鼠标的体验测试。测试结论必须以具体提交的 Actions 结果和产物为准。

仍需真实桌面验收：自绘标题栏、管理员应用、混合 DPI、多屏切换、应用最小尺寸钳制和与其他窗口工具并用。当前没有内容语义、真实眼动或可证明的用户偏好模型；避免把启发式评分包装为“已经理解每次意图”。
